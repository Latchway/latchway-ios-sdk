# Latchway iOS SDK 1.2.0

Native-owned shared accounts with developer-supplied ID tokens. Swift and React
Native may configure first and reuse one native app/session without a Firebase
dependency or a native bootstrap coordinator.

- Public `signIn`, `restore`, `currentAccount`, and opaque account handles for
  `makeClient`, `updateIdToken` and `logout`.
- Pure issuer/project metadata helpers and App Attest defaults in the existing
  `LatchwayAppAttest` module. Application authentication remains application-owned.
- Gateway-verified replacement tokens, memory-only provider tokens, temporary
  expiry suspension and generation/cancellation fencing before an account exists.
- Shared native/RN session and refresh coordination, persisted offline logout,
  account-scoped component cleanup and guarded legacy storage migration.
- Existing URLSession and Foundation Models integrations remain available.

Requires server 1.1.0 for the new supplied-identity/shared app path, with explicit
required-attestation shared caller policy. React Native 1.2.0 pins this native
release. Legacy constructors retain wire 2; shared apps use wire 3.

Install through Swift Package Manager tag `v1.2.0` or CocoaPods
`Latchway/AppAttest`, version `1.2.0`. See
[the supplied-identity guide](../../Documentation/SuppliedIdentity.md).

Local Swift, transport, lifecycle, App Attest fixture and bridge tests accompany
this release. Physical two-account, extension-process and Play acceptance are
separate; no new device evidence is implied by publication.
