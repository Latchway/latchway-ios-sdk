# Latchway iOS SDK 1.3.0

Use `try await app.signOut()` to clean up the current shared native/React Native
account without fetching an account handle or generation snapshot. This additive
API supports active or expired identities, pending sign-in, interrupted cleanup,
cold-start persisted sessions, and calls made before any account is activated.

Sign-out fences old identity work and streams, removes local account/component
credentials, and records logout intent. Concurrent calls share cleanup. If
secure storage is unavailable, the operation throws `cleanupRequired`, keeps the
app blocked, and can be retried with the same call. After success, explicit
`signIn` creates a fresh generation for the same or a different user. Old
account/client logout callbacks cannot affect that newer generation.

No new server deployment, wire protocol, public API removal, dependency or
Firebase integration is required. External provider sign-out remains owned by
the application. This does not reset quotas or revoke remote installations.
Account-scoped installation/App Attest/component key identity and non-secret
logout/retention markers remain under the existing bounded retention policy;
unrelated Keychain and authentication-provider data are untouched.

Install SwiftPM tag `v1.3.0` or CocoaPods `Latchway/AppAttest` version `1.3.0`.
See [the supplied-identity guide](../../Documentation/SuppliedIdentity.md).
This release's local lifecycle tests do not claim fresh physical-device or
extension attestation evidence.
